Windows 本地部署 Peach 聊天模型，并通过 Tailscale 接入 Linux Docker 版 AstrBot：完整实战教程

教程：

温馨提示：全部实操用时约需2+小时

从 Ollama 安装、GGUF 导入、人格配置，到安全开放 API、连接 Docker 容器中的 AstrBot，以及本地模型的日常启停。

本文根据一套实际跑通的环境整理：Windows 11 + RTX 3060 8GB + 16GB 内存；云服务器 OpenCloudOS 9.6 + 宝塔 + Docker，AstrBot 4.26.7，Napcat 与 AstrBot 分别运行在Docker容器中。

请注意：文中的 Tailscale IP 均使用占位符，执行前必须替换成自己设备的实际地址。不要把 Ollama 的 11434 端口公开到互联网。

1. 最终效果与架构

本方案不是把模型部署到云服务器，而是让 Windows 本地电脑负责推理，云服务器继续运行机器人和消息平台适配器。AstrBot 通过兼容 OpenAI 格式的 HTTP API 请求本地 Ollama。

消息与推理链路：

顺序 组件 作用
1 QQ 私聊 用户发送消息
2 Napcat（Docker 容器） 接收并转发 QQ 消息
3 AstrBot（Docker 容器） 处理消息、人格与上下文
4 Tailscale 私有网络 安全连接云服务器与本地电脑
5 Windows 11 上的 Ollama 通过 HTTP API 提供模型服务
6 Peach-Framboise GGUF 模型 执行本地文本推理
7 RTX 3060 8GB 承担主要 GPU 推理工作

请求方向： QQ 私聊 → Napcat → AstrBot → Tailscale → Windows Ollama → Peach-Framboise → 生成回复后沿原链路返回 QQ。

链路说明：

  • Windows 本机安装 Ollama，并使用 NVIDIA 显卡运行量化后的 Peach 模型。
  • Windows 与 Linux 云服务器加入同一个 Tailscale 网络。
  • Ollama 只监听 Windows 自己的 Tailscale IP；Windows 防火墙只放行云服务器对应的 Tailscale IP。
  • AstrBot 容器通过 Windows 的 Tailscale IP 请求模型，不需要在云服务器上租 GPU。

2. 实测环境与模型选择

项目 本教程使用的配置
本地系统 Windows 11
本地显卡 NVIDIA RTX 3060 8GB VRAM
本地内存 16GB RAM
本地模型 Peach-2.0-9B-8k-Roleplay，GGUF Q4_K_M
模型文件大小 约 5.33GB（不同仓库页面显示可能略有差异）
模型运行器 Ollama for Windows
云服务器 OpenCloudOS 9.6 x86_64，宝塔面板
机器人 AstrBot 4.26.7 + Napcat，均运行在 Docker 中
私有网络 Tailscale

本机有 8GB 显存，可以尝试 Q4 量化的 9B 模型；但显存还要容纳上下文缓存与其他程序。4096 tokens 是保守起点；如果人格提示词、聊天历史或记忆内容太长，可能需要增加到 8192 tokens，同时检查显存占用。 这不代表所有 8GB 显卡都能在 8192 tokens 下全程 GPU 推理。

模型仓库：Peach-2.0-9B-8k-Roleplay-GGUF（Hugging Face）。仓库提供多种量化格式，本案例选择 Q4_K_M。

注：该模型在后续使用过程中发现“无法通过修改人格提示词等多种方式使其不再出现回复内容中描述动作 ”（可能是该模型在训练时极大程度的加强了动作场景等描述，以及指令遵循能力不够强）

14. 在 AstrBot 中添加 Ollama 提供商

这一步在 AstrBot WebUI 里完成。

14.1 新增模型提供商

进入 提供商（Providers）→ 对话补全（Chat Completion）→ 新增，选择 Ollama。

填写：

项目 填写值
提供商名称 Peach-本地模型（可自定义）
API Base URL http://WIN_TS_IP:11434/v1
API Key ollama
模型 peach-framboise:latest

务必将 WIN_TS_IP 换成 Windows 本地机的 Tailscale IP。这里的地址需要带 /v1，不要把 /api/tags 当作 Base URL。

点击 保存并获取模型 / Save and Fetch Models，在列表中找到 peach-framboise:latest，点击旁边的 + 添加并启用。如果自动获取模型失败，也可以保存提供商后通过自定义模型添加精确的模型 ID。

14.2 将它设为当前对话模型

进入 配置（Config）→ 当前使用的配置文件 → AI → Model，将 Chat Model / 对话模型 选择为刚添加的 Peach-本地模型/peach-framboise:latest，保存配置。

然后使用 AstrBot 的模型测试功能，或通过 QQ 私聊机器人发送一句短消息。

官方步骤参考：AstrBot：接入 Ollama 与 AstrBot：LLM 提供商。

16.2 完全关闭本地 API 服务

  1. 在 Windows 右下角系统托盘中找到 Ollama。
  2. 右键选择 Quit Ollama。
  3. 不要停止或退出 Tailscale，除非你也希望关闭私有网络连接。

这样云服务器就不能再访问 Windows 的 Ollama API。若 AstrBot 当前默认模型仍设为 peach-framboise:latest，机器人使用该模型时会请求失败；应先把 AstrBot 的默认对话模型切换到可用的 DeepSeek 等云端模型，再退出 Ollama。

  • 不要删除模型：ollama stop 是卸载运行中的模型；ollama rm peach-framboise 才是删除模型标签，本文不需要执行删除命令。

17. 常见故障排查

现象 常见原因 排查方式
redirect target not allowed ... 198.18.0.132 下载跳转的 DNS 解析与安全检查冲突，可能涉及代理 Fake-IP 使用浏览器下载仓库中的 GGUF 文件，再通过 Modelfile 导入；不要关闭安全检查
ollama list 看不到模型 创建失败、模型名称不一致或 Ollama 使用了另一套模型目录 检查 ollama list、OLLAMA_MODELS 和 ollama create 的输出
云服务器无法访问 11434 OLLAMA_HOST 还在监听 localhost、Tailscale 未连接或 Windows 防火墙没放行 检查 Windows 监听地址、tailscale status 与防火墙来源 IP
宿主机能访问，容器不能访问 Docker 容器网络或工具缺失 在容器内部执行 /api/tags 测试，再查容器网络，不要直接公开端口
request exceeds the available context size (4096 tokens) 系统提示词、聊天记录、记忆内容超过上下文窗口 对 8K 上下文模型可试 num_ctx 8192，然后检查显存与响应速度
首次请求很慢 模型尚未加载进显存，需要冷启动 先等一会儿；通过 ollama ps 检查模型状态
机器人关闭本地模型后不回复 AstrBot 仍把本地模型设为默认模型 恢复 Ollama 服务，或先在 AstrBot 里切换到可用的云端模型
模型有 API 但输出奇怪 模型模板、系统提示词、停止标记或模型本身的生成习惯 不要盲目复制其他架构的 TEMPLATE；先保持默认模板，用短提示词测试

18. 整体验收清单

部署完成后，逐项打勾：

  • ollama list 中存在 peach-framboise:latest。
  • Windows 本机 /api/tags 可以正常返回模型列表。
  • Windows 的 11434 端口只监听本地 Tailscale IP。
  • Windows 防火墙只允许指定的云服务器 Tailscale IP 访问 TCP 11434。
  • Linux 上 tailscale status 能看到 Windows 设备。
  • Linux 宿主机请求 http://WIN_TS_IP:11434/api/tags 成功。

  • QQ 私聊机器人能返回本地模型生成的消息。
